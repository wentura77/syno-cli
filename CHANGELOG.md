## [0.2.0] - 2026-11-09

### Добавлено

#### Архитектура и ядро SDK
- Высокоуровневый асинхронный контекстный менеджер `SynoDSM` (`syno_cli.facade`), объединяющий все подсистемы NAS (`core`, `files`, `docker`, `downloads`, `logs`, `vmm`) с автоматическим закрытием сетевых соединений при выходе из контекста.
- Базовый HTTP-клиент `BaseSynoClient` с поддержкой автоматического обнаружения эндпоинтов (`SYNO.API.Info`), управления сессиями (`sid`), прозрачного перелогина при истечении токена (коды `105`, `106`, `107`, `119`) и изоляции соединений (`Connection: close`, пул `max_keepalive_connections=0` для исключения полузакрытых сокетов DSM).
- Потоковый механизм скачивания `stream_download` и выгрузки файлов `upload_file` (multipart/form-data) блоками без переполнения оперативной памяти, пригодный для работы с файлами и ISO-образами размером 8+ ГБ.
- Модуль констант `syno_cli.constants` с вынесением протокольных кодов ошибок DSM, таймаутов, размеров буферов передачи данных и кодов завершения процесса (`ExitCode`).

#### Безопасность и хранение данных
- Аппаратное симметричное шифрование сохраненных сессий (`.syno_session.json`) и учетных данных (`credentials.enc`) алгоритмом Fernet (AES-128-CBC + HMAC-SHA256) с динамической деривацией ключа через `PBKDF2HMAC` (100 000 итераций) на основе уникального отпечатка оборудования (`machine-id` в Linux или `IOPlatformUUID` в macOS) и прав доступа `0600`.
- Поддержка системной связки ключей ОС (`keyring`) в качестве альтернативного защищенного бэкенда для паролей и сессий.
- Поддержка двухфакторной аутентификации DSM (2FA / OTP-коды).
- Поддержка иерархии путей конфигурации и кэша по стандарту XDG через `platformdirs`.

#### Подсистема Core и системный мониторинг
- Клиент `SynoCoreClient` для запроса сводного статуса устройства (модель, версия DSM, температура, аптайм) и метрик утилизации CPU/RAM.
- Диагностика дисковой подсистемы, томов и физических накопителей со SMART-статусами и температурными показателями.
- Команды безопасного выключения (`shutdown`) и перезагрузки (`reboot`) NAS.

#### Container Manager (Docker и Docker Compose)
- Клиент `SynoDockerClient` с поддержкой управления жизненным циклом контейнеров: листинг (`ps`), запуск (`start`), остановка (`stop`), перезапуск (`restart`) и удаление (`rm`, включая принудительное `--force`).
- Создание и запуск контейнеров (`run`) с пробросом портов, монтированием томов и переменными окружения.
- Стриминг метрик утилизации ресурсов контейнерами в реальном времени (`stats`: CPU, RAM, дисковый I/O, сетевой трафик RX/TX).
- Чтение журналов событий контейнеров (`logs`) с нормализацией сортировки в естественный хронологический порядок.
- Управление локальными Docker-образами: просмотр списка (`images`) и загрузка из реестров (`pull`).
- Полная поддержка проектов Docker Compose (`SYNO.Docker.Project`): вывод списка (`compose list`), развертывание и обновление стеков (`compose up`), остановка (`compose down`), перезапуск (`compose restart`) и агрегированные логи (`compose logs`).

#### Virtual Machine Manager (VMM)
- Клиент `SynoVmmClient` с интеграцией с актуальным эндпоинтом DSM 7.x `SYNO.Virtualization.Guest` и сохранением обратной совместимости.
- Автоматическое обнаружение хостов-гипервизоров (`SYNO.Virtualization.Host`), репозиториев хранения (`SYNO.Virtualization.Repo`) и виртуальных сетей (`SYNO.Virtualization.Network`).
- Расширенное создание виртуальных машин (`vm create`):
  - Поведение и службы: автозапуск при старте NAS (`--autorun`), синхронизация времени с DSM (`--sync-time`), профиль ОС (`--windows` / `--linux`), текстовое примечание (`--desc`).
  - Сетевые интерфейсы: выбор виртуальной сети (`--network`) и статический MAC-адрес (`--mac`).
  - Процессор и производительность: прямой проброс флагов CPU (`--cpu-passthrough`), оптимизации Hyper-V (`--hyperv`), приоритет планировщика (`--cpu-weight`), привязка ядер (`--cpu-pin`).
- Управление питанием гостевых ОС (`poweron`, мягкое ACPI-выключение `shutdown`, принудительное отключение `poweroff`, перезапуск `restart`).
- Создание моментальных снимков состояния виртуальных машин (`vm snapshot`).
- Просмотр и регистрация/импорт образов ISO/дисков (`vm images`, `vm image-import`).

#### File Station
- Клиент `SynoFileStationClient` с просмотром файлов и каталогов (`ls`) с определением типов файлов, иконками и сортировкой по дате/размеру.
- Создание папок (`mkdir`), удаление (`rm`), перемещение/копирование (`copy_or_move`) и генерация публичных ссылок обмена (`create_sharing_link`).
- Интерактивные прогресс-бары Rich для операций скачивания (`download`) и загрузки (`upload`).
- Динамическое автодополнение путей файловой системы NAS в командной строке по нажатию клавиши `Tab`.

#### Download Station
- Клиент `SynoDownloadStationClient` с просмотром очереди задач и суммарных скоростей передачи (`download list`).
- Добавление задач по URL, magnet-ссылкам, а также прямая загрузка локальных `.torrent`-файлов по multipart/form-data (`download add`).
- Автоматическая нормализация путей сохранения (`--dest`) с обработкой прямых и обратных слэшей.
- Приостановка (`pause`), возобновление (`resume`) и удаление (`delete`) задач.

#### Системные журналы (Log Center)
- Клиент `SynoLogsClient` (`SYNO.Core.SyslogClient.*`) для чтения системных логов DSM.
- Команда `syno logs list` с фильтрацией по уровням критичности (`info`, `warn`, `err`), поиском по ключевым словам и форматированием.

#### Консольный интерфейс и визуализация
- Централизованный декоратор `@cli_command` с плоским диспетчером исключений, Rich-спиннером и стандартизированными кодами возврата процесса (`ExitCode`).
- Строгий псевдоним типов `CommandResult` для функций команд CLI.
- Полнофункциональный вывод в формате неформатированного JSON (`--json` / `-j`) для всех команд с разделением потоков `stdout` и `stderr`.
- Таблицы и панели визуализации на базе библиотеки Rich: форматирование размеров данных, скоростей, времени аптайма и цветовая маркировка статусов.

#### Тестирование и качество кода
- 100% покрытие строгой статической типизацией (`mypy --strict`).
- Оформление документации по стандарту PEP 257 (Google-style docstrings) с порогом проверки `interrogate >= 90%`.
- Набор тестов с мокированием сетевого транспорта (`httpx.MockTransport`) для аутентификации, криптографии, подсистем (Docker, Compose, VMM, Download Station, Logs), фасада `SynoDSM`, а также обработки таймаутов и сетевых сбоев.
